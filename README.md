# Шаблон лендинга

Технический каркас сайта на Next.js: приём заявок, SEO, аналитика, юридические
страницы — всё уже написано и работает.

**Дизайна и секций здесь нет намеренно.** Их ты делаешь сам — это твой сайт,
а не копия чужого. Шаблон снимает с тебя настройку окружения и SEO-обвязку,
чтобы лимиты ушли на дизайн и содержание, а не на конфиги. Если ты открыл
его в ожидании готового сайта — готового сайта тут нет, тут есть фундамент,
на котором его быстро собрать.

## Что нужно

- Аккаунт GitHub и аккаунт Vercel — оба бесплатные
- VS Code с расширением Claude Code — ставится из маркетплейса VS Code
  по названию «Claude Code»; там ты и разговариваешь с Claude
- Node.js 24 или новее — [nodejs.org](https://nodejs.org): обычный
  установщик, «Далее — Далее — Готово», терминал не нужен
- Git — им VS Code клонирует репозиторий на третьем шаге. Не установлен —
  VS Code скажет об этом сам и даст ссылку ([git-scm.com](https://git-scm.com)),
  на macOS диалог ставит его кнопкой

Node нужен для того, чтобы сайт запускался **у тебя на компьютере**;
pnpm поверх него Claude поставит сам, командовать этим не придётся. Пока
Node не стоит, шаги 1–3 быстрого старта всё равно проходят: сайт собирает
Vercel на своих серверах, и он уже открыт по своему адресу.

## Быстрый старт

Терминал для этого не нужен ни разу: команды выполняет Claude, сборку —
Vercel.

1. **Скопируй шаблон.** Кнопка **Use this template** → **Create a new
   repository**. Получится твой репозиторий с этим кодом.
2. **Задеплой его.** [vercel.com/new](https://vercel.com/new) → войди
   в Vercel через GitHub, чтобы он увидел твои репозитории → Import Git
   Repository → выбери свой → **Deploy**. Настраивать нечего:
   Next.js Vercel узнаёт сам. Через пару минут сайт открыт на адресе вида
   `имя-проекта.vercel.app`. Красный `pnpm test` этому не мешает: сборка
   тесты не гоняет, `pnpm build` — это `next build` и ничего больше.
3. **Открой сайт и собери материалы.** На первом экране — **чек-лист того,
   что нужно принести**: тексты о бизнесе, услуги и цены, отзывы, фото,
   контакты, реквизиты, референсы. Ставь галочки по мере сбора — они
   хранятся в твоём браузере. Это самый долгий шаг, и он не про код.
4. **Открой проект в VS Code.** Source Control → Clone Repository → вставь
   ссылку на свой репозиторий. Тоже мышью.
5. **Скажи Claude `/start`.** Дальше ведёт он: поставит зависимости,
   **спросит по разделам и запишет ответы в `brief.md` сам** — размечать
   markdown и заполнять таблицы руками не нужно, — перенесёт бриф в конфиг,
   спросит в чате домен (своего ещё нет — годится адрес от Vercel из шага 2),
   прогонит проверки, запустит сайт локально и **запушит** сделанное,
   чтобы Vercel пересобрал твой живой сайт.

Чек-лист исчезнет сам, когда в конфиге не останется заглушек шаблона, —
удалять его руками не нужно, и на месте первого экрана окажется обычная
главная. На сайте в интернете это случится не в момент заполнения,
а после пуша: Vercel собирает то, что лежит в GitHub.

`.env.local` Claude создаёт сам на пятом шаге. В git он не попадает
и с пустыми значениями ничего не ломает: форма работает в демо-режиме,
счётчики просто не рендерятся.

Фавикона шаблон не везёт — положи свой в `app/icon.png` (512×512), и Next
сам сделает из него и `<link rel="icon">`, и `/favicon.ico`. Пока файла нет,
`/favicon.ico` отдаёт честный 404.

### Если хочешь запускать сам

Ничего из этого делать не обязательно — те же команды выполняет Claude
по просьбе. Но если терминал тебе привычнее:

```bash
pnpm install
pnpm setup                   # 5 вопросов, заполнит lib/site.ts
cp .env.example .env.local   # переменные окружения; можно оставить пустыми
pnpm dev
```

| Команда | Что делает |
| --- | --- |
| `pnpm setup` | необязательно: 5 вопросов и заполненный `lib/site.ts` (только вручную в терминале) |
| `pnpm dev` | запустить разработку |
| `pnpm test` | тесты и проверка заглушек |
| `pnpm test:unit` | те же тесты без guard-а заглушек |
| `pnpm lint` | проверка типов |
| `pnpm check-brief` | что осталось заполнить в брифе (`0/70` на свежем шаблоне) |
| `pnpm build` | сборка |

`pnpm setup` — не обязательный шаг, а короткая дорога для тех, кто набирает
быстрее, чем диктует: пять ответов уходят в `lib/site.ts` без единого
токена модели. Пропустишь — ничего не потеряешь: те же поля заполнит
`/brand-init` из брифа, а домен спросит в чате. Запустить его может только
человек руками — скрипт ждёт ответы по одному и на не-интерактивном вводе
(в том числе от Claude) отказывается работать.

## Как работать

1. **Собери материалы по чек-листу** с первого экрана сайта. Он же —
   разделы `brief.md`: о бизнесе, структура, контент, визуал, контакты,
   реквизиты, домен.
2. **Скажи Claude `/start`** и продиктуй собранное в чате. Он спросит
   по разделам, разложит ответы по полям и запишет `brief.md` сам.
   Бриф — источник правды по проекту: заполнив его один раз, ты больше
   не пересказываешь в каждом новом чате, чем занимается компания и какой
   у тебя телефон.
   Отдельно звать `/brand-init` не нужно — он шаг внутри `/start`. Зови его
   сам, только когда бриф уже заполнен и данные надо перенести заново:
   поменялся телефон, купили домен. Домен лежит в Блоке Б, а нужен сразу:
   если поле пустое, Claude спросит его одним вопросом в чате и **впишет
   ответ обратно в бриф**, чтобы бриф и конфиг не разошлись.
3. **Собирай свой сайт:** `/new-section` — блок на главной (преимущества,
   отзывы, FAQ, цены), `/new-page` — новая страница со всей SEO-обвязкой.
4. **Скажи `/ship`, когда что-то готово.** Он прогонит проверки,
   закоммитит и запушит, а Vercel сам пересоберёт сайт из этого коммита.
   Пока не запушено, на твоём адресе висит то, что было, — этим шагом
   сделанное и попадает в интернет.

**`pnpm test` красный на свежем шаблоне — так и надо.** В нём шесть
заглушек в `lib/site.ts`: домен, телефон, номер WhatsApp, БИН, название
компании, юридическое лицо. Все шесть закрывает `/brand-init` из заполненного
брифа. Деплою красный guard не мешает: Vercel собирает `next build`, тесты
в сборку не входят. Пока идёт работа над кодом, гоняй `pnpm test:unit` —
он те же тесты без guard-а и обязан быть зелёным.

## Что внутри

| Путь | Что это |
| --- | --- |
| `brief.md` | бриф проекта — источник правды |
| `lib/site.ts` | вся конфигурация сайта — правишь только его |
| `lib/content/` | тексты: правка заголовка не требует чтения компонента |
| `components/sections/` | секции сайта — их добавляет `/new-section` |
| `components/dashboard/` | чек-лист первого экрана; исчезает вместе с заглушками |
| `lib/lead/`, `components/lead/` | приём заявок: схема, отправка, форма |
| `components/seo/` | разметка для поисковиков |
| `components/analytics/` | счётчики и трекер кликов |
| `.claude/skills/`, `.claude/commands/` | команды для Claude — работают сразу |

## Заявки

Токены живут в `.env.local` — скопируй его из `.env.example`, если ещё не сделал
этого на быстром старте. Пока не заполнены `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_CHAT_ID`, форма работает в **демо-режиме**: отвечает успехом и печатает
заявку в консоль. Это нормально — бота подключают в конце. Чтобы уводить заявки
в почту или CRM, положи свой файл рядом с `lib/lead/providers/telegram.ts`.

## Юридические страницы

Тексты политики конфиденциальности и оферты — **шаблонные**. Перед запуском
сайта их обязан проверить юрист. Мы не несём ответственности за их содержание.

## Публикация

Перед публикацией переключи `SITE.indexable` на `'public'` — пока стоит
`'private'`, сайт закрыт от поиска, `sitemap.xml` пустой, а Lighthouse
ставит низкий балл по SEO. Это защита от того, чтобы черновик уехал
в индекс, а не поломка.

Скажи Claude `/deploy` — он проведёт по шагам: переменные окружения, свой
домен вместо адреса `*.vercel.app`, проверка на бою. Сам проект в Vercel
уже есть с шага 2 быстрого старта, и каждый твой коммит в GitHub
пересобирает его автоматически. Перед публикацией полезно `/seo-check`.

# CLAUDE.md — шаблон лендинга

## Что это

Технический каркас лендинга на Next.js 16 + React 19 + TypeScript + Tailwind 4,
деплой в Vercel. Секций и оформления здесь нет намеренно — их делает автор сайта.

## С чего начать

1. Заполнить `brief.md` — это источник правды по проекту.
2. `/brand-init` — заполнить `lib/site.ts` из брифа.
3. `pnpm test` — guard-тест должен позеленеть.

## Ключевые правила

1. **Файл не длиннее 150 строк.** Каждая секция — отдельный компонент
   в `components/sections/`. Монолитная страница делает каждую правку
   дизайна дорогой: приходится читать и переписывать весь файл.
2. **Весь текст — в `lib/content/*.ts`**, не в JSX. Правка заголовка
   не должна требовать чтения компонента.
3. **Контакты, реквизиты, домен — только через `SITE`** из `lib/site.ts`.
   Никогда не хардкодить телефон, домен или БИН.
   `SITE` закрыт `as const`, поэтому поля имеют литеральные типы: сравнивая
   поле со строкой, сначала расширь тип — `(SITE.domain as string) !== '…'`.
   Иначе `tsc` выдаст TS2367, как только поле заполнено.
4. **Данные проекта брать из `brief.md`, а не переспрашивать пользователя.**
   Формат поля жёсткий: `- **Название:**`, двоеточие внутри жирного.
   Подсказку в скобках нельзя ставить после двоеточия — парсер сочтёт её
   заполненным значением.
5. Не включать `typescript.ignoreBuildErrors`, `eslint.ignoreDuringBuilds`,
   `images.unoptimized`.
6. Метадата только через `generateMetadata` или `export const metadata`.
   Никаких сырых тегов `<head>`. Никогда не добавлять `keywords`.
7. Счётчики только через `<SiteAnalytics/>` из переменных окружения.
   Не вставлять идентификаторы GTM или Метрики в код.
8. FAQ — серверный `<details>`, а не аккордеон на `useState`:
   ответы должны присутствовать в HTML, иначе их не увидят
   ни поисковики, ни AI-краулеры.
9. Никакого `aggregateRating` и `Review` без реального проверяемого
   источника — это основание для ручной санкции поисковика.
10. Не `new Date()` в `sitemap.lastModified` — правится константа
    `LAST_UPDATED` в `lib/seo.ts`.
11. **Не менять пути** `lib/site.ts`, `lib/content/*`, `components/sections/*` —
    на них держится переезд на шаблон многостраничника.

## Где что лежит

- `brief.md` — бриф проекта, источник правды
- `lib/site.ts` — вся конфигурация сайта
- `lib/seo.ts` — канонические адреса, режим индексации, дата обновления
- `lib/lead/` — схема заявки, провайдер отправки, лимит частоты
- `components/lead/` — форма, модалка, событийная шина
- `components/seo/json-ld.tsx` — разметка для поисковиков
- `components/analytics/` — счётчики и трекер кликов
- `tests/placeholders.test.ts` — guard: заглушки должны быть заменены

## Команды

- `pnpm dev` — разработка
- `pnpm lint` — проверка типов (`tsc --noEmit`)
- `pnpm test` — тесты и guard заглушек
- `pnpm check-brief` — что осталось заполнить в брифе
- `pnpm build` — сборка

## Не принять за баги

1. **Форма без `TELEGRAM_BOT_TOKEN` работает в демо-режиме**: отвечает успехом
   и печатает заявку в консоль. Так задумано — бот подключается в конце.
2. **Лимит частоты живёт в памяти процесса**: не переживает перезапуск
   и не общий между инстансами. От тупого флуда защищает,
   от целенаправленного — нет. Известное ограничение, не регрессия.
3. **`indexable: 'private'` по умолчанию** — `robots.txt` закрывает сайт,
   `sitemap.xml` пустой, `llms.txt` отдаёт 404. Пока стоит `'private'`,
   Lighthouse ставит низкий балл по SEO — это следствие настройки,
   а не проблема кода. Переключить на `'public'` перед запуском.
4. **`agentRules: false` в `next.config.mjs` — намеренно.** Иначе Next
   создаёт свой `AGENTS.md` и дописывает блок в этот файл.
5. **`@theme inline` в `app/globals.css` удалять нельзя.** В Tailwind 4
   утилита существует только если токен зарегистрирован там. Ошибка
   `Cannot apply unknown utility class X` значит, что для `X` нет
   строки `--color-X`.
6. **Здесь `typescript@5.9.3`, а не `7.x` — сознательный откат.** TS7
   на чистом каркасе (до первого `next build`/`dev`) роняет `tsc --noEmit`
   ошибкой `TS2882` на side-effect-импорте `./globals.css`: нужную
   ambient-декларацию `*.css` приносит `next-env.d.ts`, а его ещё нет.
7. **`allowImportingTsExtensions: true` в `tsconfig.json` обязателен.**
   `scripts/check-brief.ts` импортирует `../lib/brief.ts` с расширением —
   так требует Node при прямом запуске TS-файла, а `tsc` без флага
   такой импорт запрещает (`TS5097`).
8. **`pnpm-workspace.yaml` — не мусор.** Список исключений из встроенной
   в pnpm проверки «возраста» пакета; без него установка периодически
   падает `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`. Когда пакеты
   состарятся, записи станут декоративными.
9. **`next-env.d.ts` меняется сам.** Путь внутри осциллирует между
   `./.next/dev/types/…` и `./.next/types/…` в зависимости от того,
   что запускали последним — `dev` или `build`. Дифф почти в каждом
   коммите — это нормально, коммить можно любой вариант.
10. **`shadcn` в `devDependencies` — не ошибка.** `app/globals.css`
    импортирует `shadcn/tailwind.css`, который резолвится в файл
    внутри пакета; без него сборка падает.
11. **`SITE` закрыт `as const`** — поля имеют литеральные типы (правило
    и пример см. «Ключевые правила», п. 3). Без явного расширения типа
    сравнение поля со строкой роняет `tsc` ошибкой TS2367.
